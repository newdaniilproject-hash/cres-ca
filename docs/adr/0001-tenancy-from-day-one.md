# ADR 0001. Мультиарендность с первой миграции

**Дата:** 2026-08-03 · **Статус:** принято

## Контекст

Продукт начинается как склад и учёт для одного ФОПа, а должен вырасти
в маркетплейс, где у каждого продавца свой магазин. Напрашивается соблазн
сделать сначала простую однопользовательскую систему, а мультиарендность
добавить, когда придёт второй клиент.

Аудит предыдущего проекта показал, во что это обходится. В базе на 77 таблиц
не нашлось ни одной колонки `tenant_id`, `shop_id` или `merchant_id`. Все
140 политик доступа проверяют «ты вообще администратор», а не «ты
администратор этого магазина» — то есть второй продавец в тот же день
увидел бы заказы первого. Уникальность артикулов и адресов товаров была
глобальной: второй продавец не смог бы завести товар с занятым SKU. Номера
заказов шли из одной последовательности на всю базу. Права людей были
прошиты триггером на два конкретных адреса почты.

Переделка такой схемы — это миграция живых заказов, остатков и денег
с простоем и риском потери данных.

## Решение

Каждая таблица данных несёт `tenant_id` с первой миграции. Все уникальные
ограничения составные: `(tenant_id, sku)`, `(tenant_id, slug)`. Нумерация
документов — пер-арендаторная, через счётчики, а не через глобальные
последовательности.

Переход «склад для одного ФОПа» → «магазин на маркетплейсе» реализован
флагом `tenants.storefront_enabled`. Данные не двигаются: включается
публичная витрина у арендатора, который уже существует.

## Следствия

Проектирование дороже примерно на неделю. Каждый запрос обязан фильтровать
по арендатору, каждая политика RLS — проверять членство.

Взамен: второй, десятый и тысячный продавец не требуют миграции. Первый
клиент, которому обещан «перенос склада в маркетплейс», получает его
переключением флага, а не переездом.

## Альтернативы

**База на арендатора.** Полная изоляция, но невозможен общий каталог —
а он и есть суть маркетплейса. Отклонено.

**Схема на арендатора в одной базе.** Изоляция лучше, но миграции надо
прогонять по каждой схеме, и на сотнях арендаторов это перестаёт
работать. Отклонено.

**Общие таблицы + RLS.** Выбрано. Общий каталог получается бесплатно,
изоляция обеспечивается политиками, миграция одна на всех.
