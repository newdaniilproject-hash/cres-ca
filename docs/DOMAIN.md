# Общие правила системы

То, что одинаково для всех продавцов и всех покупателей. Продавец может
поменять внешний вид витрины, но не может поменять то, что описано здесь —
иначе покупатель, переходя между магазинами, перестанет понимать интерфейс.

Каждый список статусов ниже — источник правды. Он живёт в одном месте
(`lib/domain/`), оттуда берутся названия, цвета, разрешённые переходы
и тексты уведомлений. Добавить статус в компоненте нельзя.

---

## Кто есть кто

**Покупатель** — любой человек. Может смотреть каталог без регистрации,
но для заказа и записи нужен подтверждённый телефон.

**Продавец** — предприниматель. На платформу допускаются только
зарегистрированные ФОПы и юридические лица; это не удобство, а требование
законодательства о цифровых платформах, снимающее с площадки обязанности
налогового агента.

**Сотрудник магазина** — человек, приглашённый продавцом. Роль относится
к конкретному магазину: один и тот же человек может быть владельцем одного
и кладовщиком в другом.

**Сотрудник платформы** — проверка продавцов, модерация, споры. Единственная
глобальная привилегия в системе.

---

## Жизненный цикл магазина

```
черновик → на проверке → активен ⇄ приостановлен → архив
```

**Черновик.** Создан после первого шага регистрации. Продавец наполняет
каталог, витрины нет.

**На проверке.** Продавец подал заявку на публикацию. Платформа сверяет
реквизиты с реестром, смотрит каталог. Срок — один рабочий день.

**Активен.** Витрина опубликована. Отдельно решается, показывать ли товары
в общем каталоге маркетплейса: магазин может быть открыт, но временно скрыт
из общей выдачи.

**Приостановлен.** Неоплата или нарушение. Витрина закрыта, кабинет работает,
данные целы. Существующие заказы можно довести до конца.

**Архив.** Продавец ушёл. Данные хранятся, доступ закрыт. Полное удаление —
только по заявлению и с выгрузкой данных.

Переход «склад без витрины» → «магазин на маркетплейсе» отдельным состоянием
не является: это флаг публикации витрины у активного магазина. Данные при
этом не переносятся.

---

## Жизненный цикл позиции

```
черновик → на модерации → активна ⇄ скрыта → архив
```

Модерация проходится один раз при первой публикации и повторно при смене
категории или существенном изменении описания. Правка цены и остатков
модерации не требует — иначе продавец не сможет работать.

Скрытая позиция недоступна по прямой ссылке, но сохраняется в старых заказах.
Архивная не удаляется никогда: на неё ссылаются заказы и отчёты.

## Жизненный цикл заказа

Единый для всех магазинов. Продавец не может ни переименовать статус,
ни добавить свой.

| Статус | Что означает | Кто переводит |
|---|---|---|
| Новый | Оформлен покупателем, продавец ещё не видел | система |
| Подтверждён | Продавец принял в работу | продавец |
| Ожидает оплаты | Выставлен счёт, деньги не поступили | продавец |
| Оплачен | Продавец подтвердил поступление | продавец |
| Собирается | Комплектуется на складе | продавец |
| Отправлен | Передан перевозчику, есть номер отправления | продавец |
| Доставлен | Получен покупателем | продавец или перевозчик |
| Выполнен | Закрыт, запущен срок возврата | система |
| Отменён | Не состоялся | продавец или покупатель |
| Возврат | Оформлен возврат | продавец |

Разрешённые переходы описаны таблицей в коде. Произвольный переход
невозможен: нельзя отправить неоплаченный заказ с предоплатой, нельзя
отменить доставленный.

Покупатель отменяет сам только до статуса «Собирается». Дальше — через
обращение к продавцу.

**Резерв остатков.** Товар резервируется в момент оформления, а не оплаты —
иначе двое купят последнюю единицу. Резерв снимается при отмене или
по истечении срока ожидания оплаты, который задаёт продавец.

**Нумерация.** Номер заказа сквозной внутри магазина и начинается с единицы
у каждого продавца. Общей нумерации по платформе нет: продавец не должен
видеть по номеру, сколько заказов у соседей.

## Жизненный цикл записи на услугу

| Статус | Что означает |
|---|---|
| Забронирована | Клиент выбрал время |
| Подтверждена | Мастер подтвердил |
| Клиент пришёл | Отмечено на месте |
| Выполнена | Услуга оказана, можно оставить отзыв |
| Отменена клиентом | До срока отмены — свободно, после — по правилам магазина |
| Отменена мастером | Обязательно с причиной, клиенту предлагается другое время |
| Не пришёл | Влияет на возможность записи в будущем |

Двойное бронирование одного времени невозможно на уровне базы, а не проверкой
в коде: пересечение интервалов у одного мастера запрещено ограничением.
Проверка в приложении всегда проигрывает гонке двух одновременных записей.

Напоминания клиенту — за сутки и за два часа. Настройка — у продавца,
отключить полностью нельзя.

---

## Возвраты

Возврат заводится от заказа и наследует его состав. Причина обязательна.
Срок приёма заявки задаёт продавец, но не меньше установленного законом
для дистанционной торговли.

Возврат денег платформа не выполняет — деньги шли напрямую продавцу.
Система только фиксирует факт и корректирует учёт: позиции возвращаются
на склад, доход по заказу снимается. Реальный перевод делает продавец.

---

## Отзывы и рейтинг

Отзыв оставляет только тот, у кого есть выполненный заказ или выполненная
запись на эту позицию. Отзывов без покупки не бывает — это единственная
защита рейтинга, которая работает.

Оценка от одного до пяти, текст необязателен, фото до пяти штук. Изменить
можно в течение двух недель, потом фиксируется.

Продавец отвечает на отзыв, но не удаляет его. Пожаловаться может, решает
платформа.

Рейтинг позиции и рейтинг магазина считаются пересчётом при изменении,
а не запросом при каждом показе. Магазин с числом отзывов меньше пяти
показывает «мало оценок» вместо цифры — средняя по двум отзывам не значит
ничего.

---

## Переписка

Диалог привязан к паре «покупатель — магазин» и, если есть, к заказу.
Общая переписка не по заказу тоже возможна: вопрос о товаре до покупки.

Правила одинаковы для всех: сообщения хранятся, редактирование запрещено,
удаление скрывает для отправителя. Продавец видит всю историю с покупателем,
покупатель — только свою.

Контакты не скрываются и не подменяются. Платформа не в потоке денег,
поэтому обходить её через прямую связь бессмысленно — прятать телефон
незачем.

---

## Уведомления

Три канала: внутри системы, электронная почта, мобильное уведомление.
Телефонные сообщения — платно и только критичное.

Событие описывается один раз: кому, по каким каналам, с каким текстом.
Тексты — в словаре переводов, не в коде отправки.

**Покупателю:** заказ принят, статус изменился, отправлен с номером,
напоминание о записи, отмена, ответ продавца, товар снова в наличии,
просьба оценить.

**Продавцу:** новый заказ, новая запись, отмена клиентом, новое сообщение,
новый отзыв, заканчивается товар, приближается оплата тарифа,
решение платформы.

**Сотрудникам магазина:** по их разделам, с учётом прав. Кладовщик получает
уведомления о заказах и остатках, но не о деньгах.

Каждое уведомление можно отключить в настройках, кроме связанных
с безопасностью и оплатой тарифа.

---

## Учётная запись и безопасность

Вход по почте или телефону с паролем. Дополнительно — вход по одноразовому
коду без пароля.

Обязательно поддерживаются: смена пароля, восстановление по почте и телефону,
смена почты с подтверждением обоих адресов, смена телефона с подтверждением,
просмотр и завершение активных сеансов, удаление учётной записи.

При смене роли или исключении из магазина активные сеансы человека
завершаются принудительно. Иначе уволенный сотрудник сохранит доступ
до истечения токена.

Удаление учётной записи не удаляет заказы: они нужны продавцу для отчётности.
Личные данные обезличиваются, история сделок остаётся.

## Деньги, время, язык

**Валюта** — гривна. Суммы хранятся с двумя знаками, округление до копейки
по математическим правилам. Расчёты никогда не ведутся в дробных числах
с плавающей точкой.

**Время** хранится в часовом поясе UTC, показывается в поясе магазина.
Для записей на услуги пояс магазина — обязательное поле: клиент из другого
города должен видеть время мастера, а не своё.

**Язык.** Интерфейс — украинский, русский, английский. Содержимое продавца
(названия, описания) на его языке, платформа не переводит. Все строки
интерфейса из словаря; захардкоженная строка — ошибка приёмки.

**Адреса и доставка** — справочник отделений перевозчика подтягивается
из его сервиса, а не хранится вручную.

## Что платформа обязана уметь с первого дня

Не потому, что это красиво, а потому, что без этого нельзя работать
по закону или нельзя запуститься.

Проверка продавца при регистрации с сохранением доказательств: что
проверяли, когда, каким источником. Договор оферты с датой принятия
и версией. Согласие покупателя на обработку данных с журналом. Порядок
обращений и жалоб. Выгрузка своих данных по запросу — и для продавца,
и для покупателя. Журнал действий сотрудников платформы. Реквизиты
платформы на видном месте.
